---
name: create-vfx
description: Create, inspect or revise editable particles, artwork, logo reveals and game effects directly in SlotVFX Desktop. Show the result in the editor using its existing clip, focus and playback tools.
---

For game animation generation or delivery, read [animation review and budgets](../slot-vfx-motion-craft/references/animation-review.md). Use sparse curves and the selected runtime’s supported representation, then run `slotfx_review_animation` for the intended clip and copy count; review warnings without deleting artist keys automatically.

SlotVFX skills version: 0.9.12. If `slotfx_get_bridge_status` shows a newer `skills.latestVersion`, tell the user once that a SlotVFX skills update is available and how to update (`skills.howToUpdate`).

Use the connected SlotVFX tools; no source repository is needed. Start with `slotfx_get_app_state` and `slotfx_get_bridge_status`. If the bridge is unavailable, tell the user to open SlotVFX and turn on Help → Connect AI. Do not invent a connection or restart an app with unsaved work. If no `slotfx_` tools are available at all, SlotVFX isn't connected to Claude Code yet; say so plainly instead of attempting the work, and help the user connect it with [Connect SlotVFX](../slotvfx-mcp-authoring/references/connect-slotvfx.md).

For project creation/opening, use the app lifecycle tools and poll the returned operationId until terminal status, then wait for editorReady. Native save/discard/cancel dialogs are user decisions. Inspect the current project, hierarchy and clips before editing; preserve unrelated work. Resolve only missing visual decisions that matter (style, timing, target); use sensible defaults for a first draft.

Read [workflow routes and authoring checks](references/workflows.md) for tool selection, key replacement, preservation and recovery. Use the matching bundled specialist skill for detailed logo, particle, hold, travel or motion-timing recipes (read [travel effects](../slot-vfx-travel-effects/SKILL.md) only when something flies from a start to a target, such as coins or gems flying to a counter or meter, or a zap to a symbol; coin showers, fountains, bursts, rain, spinning coins and in-place pickup glows are not travel effects, so use the particle recipes for those); the guide provides common checks. For sword slashes, crescent cuts or directional attacks, read [the slash skill](../slot-vfx-slashes/SKILL.md). For the chosen effect, load only the relevant authoring guide and feature schemas. Existing logo composition knowledge and particle presets can provide a starting point. Choose effect layers, images, particles, paths or shaders to fit the requested result rather than forcing every design into particles. For a standard move on image layers (float, shake, bounce, pulse, pop-in, coin spin and similar), `slotfx_apply_motion_preset` (from 0.9.78) writes the same keys as the editor's Add motion window.

For textures, look in the shared texture library first: `slotfx_search_library` with `scopes: ["shared"]`. Don't take the first result: narrow with a descriptive query, `category`, `tags` and (where the app has it) `look` filters, open the page with `includeContactSheet: true`, shortlist three or four that fit the project's art style and each item's `look.goodFor` / `look.notFor`, check the best with `slotfx_get_library_item` (scope `shared`), then import it with `slotfx_import_asset`, `libraryItemId` and `colorMode: "auto"`. Keep this internal: describe the effect to the user, not the library search, item names or colour modes. Draw or generate a texture only when nothing there fits, or when the tool says the shared library isn't connected (older app builds). [Particle recipes](../slot-vfx-particle-recipes/SKILL.md#textures) explain choosing and the colour modes.

For a layered effect, describe the event stage by stage: what happens first, how light changes, what breaks off and what remains. Name the parts needed for the requested style and scale, give each a distinct job and motion, and coordinate their timing around shared beats. Use consistent lighting where the material calls for it. Compare references at the same on-screen size against the requested readability, material and motion; keep detail and layer count proportional to the brief.

For new visual directions, use the [visual-direction checkpoint](../slot-vfx-effect-pack/SKILL.md#establish-a-visual-direction): connect purpose to shape, motion, contrast and timing; inspect one representative effect over the real art at the intended display size before expanding the treatment. This is self-review, not an extra approval step. Keep configuration readback, observed editor appearance and tested game-runtime behavior distinct in the handoff.

When an effect reads poorly or the visual direction is open, use [visual critique and coordinated effects](references/visual-critique.md). Diagnose the dominant flaw before adding detail, compare meaningful alternatives when useful, and align FX with existing actor/symbol cues. Keep a focused revision focused; preserve approved art and unrelated drafts.

Use a new named group/clip for an alternative. Pass explicit clip membership where supported; parent-group membership can include child layers too. Read nested configuration and clip membership back after edits. Unknown properties may not produce an effect. For large key edits, use ordered batches below schema limits and retain the intended times/values for reconciliation.

The result belongs in SlotVFX. Follow the guide's editor handoff: inspect the active clip, activate the requested one if needed, select/frame the result with `slotfx_focus_entity`, then use `slotfx_play_timeline` for natural playback when showing it. Playing a named timeline alone does not switch the editor to it. Read back editor state and leave the requested effect easy to find. For particle effects, run `slotfx_check_particle_effect` and fix its FAIL and WARN rows before showing the result. Then confirm it actually draws in the editor with `slotfx_capture_viewport` during playback: `render_layout` can stack layers differently from the editor. An opaque preview backdrop added to an effect clip, in a group above the effect's group, hid every particle in the editor while renders looked right; keep preview backdrops out of effect clips. Inspect entry, peak, tail and loop behavior in the editor; use a bounded capture only for a particular diagnostic. Revise until the design reads clearly at its intended size. Report what changed and name the clip/layers to inspect. Save, record or export only when requested. Respect disabled controls and explain the exact native step rather than substituting a chat viewer.
