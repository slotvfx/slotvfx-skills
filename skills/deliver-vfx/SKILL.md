---
name: deliver-vfx
description: Export or record approved SlotVFX effects as runtime assets, editable projects or MP4/WebM, and verify the requested delivery. Use when the user asks for a SlotVFX export or recording.
---

Use this skill for an explicit save, export or recording request. Ordinary creation/revision ends with the editable result ready in SlotVFX; it does not require a media file or chat viewer. Inspect app state, the requested project, clip/group and target before exporting. Read [delivery, recording and recovery checks](references/workflows.md), adapted from the existing showcase-video and effect-pack workflows. Use the bundled showcase-video skill for detailed combining/loop review when relevant. Resolve the format/destination if it cannot be inferred; keep existing authorization. Do not treat a generic export request as permission to publish to a service. If no `slotfx_` tools are available at all, SlotVFX isn't connected to Claude Code yet; say so plainly instead of attempting the work, and help the user connect it with [Connect SlotVFX](../slotvfx-mcp-authoring/references/connect-slotvfx.md).

Use `slotfx_export_runtime` for target data/diagnostics; this MCP call writes JSON files only, not the complete engine bundle. The artifacts list includes planned scripts/assets: only fileWrite.files proves written output. Finish a full bundle through the editor Game Runtime Export when available and authorized; otherwise report that exact remaining step. Write only to a task-owned destination with overwrite:false unless replacement is authorized. Exercise the resulting runtime before claiming parity, especially for masks, Spine, audio, instances and state triggers. `slotfx_run_quick_test` with `captureFrame: true` renders one frame through the Pixi or Phaser runtime as a quick spot check. For a Spine layer, run `slotfx_check_spine_export` before exporting: it reports peak draw calls on Pixi 8, atlas pages, mesh and bone costs, and textures stored twice, which `slotfx_remove_spine_atlas_duplicates` (0.9.79) can merge after a dry run. Editor screenshots do not establish runtime correctness.

For a video, inspect `slotfx_get_recorder`, select the exact timeline or saved scenario, and start a bounded recording. Recording needs a paid export license. MP4 is opaque H.264 (AAC sound); WebM keeps transparency (VP9, VP8 fallback, Opus sound). The desktop export queue holds six jobs, counting finished jobs and exports started in the editor; free a slot only by discarding this task's own retrieved job. Retain jobId and poll `slotfx_get_recording` until job.lifecycleState is completed; only completed jobs can be delivered. `slotfx_cancel_recording` stops a task-owned job; cancellation is not a saved video. Use save_recording for a local deliverable, then poll job.saveState for saved/cancelled/failed. A successfully saved MCP recording remains job.state=ready for later retrieval; state alone does not prove a save. Use read_recording for bounded binary retrieval. Confirm actual codec, dimensions, fps, duration and frame count. For a take with sound, read the finished job's `audioMix`: gains are never normalized, so `clippedSamples` above zero means the mix clips. Report source/rendered/exported frame rates separately when they differ.

Save the editable .slotvfx project if requested. Identify actual output paths, target and limitations. If a step is interrupted, reconcile its receipt before retrying. If authentication, licensing or a native file picker needs the user, report the precise requirement and continue independent validation.
