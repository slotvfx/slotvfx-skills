# Contributing to SlotVFX skills

Contributions are welcome. You can propose a fix or a new recipe without direct write access to the repository:

1. Open an issue to describe a substantial change, or fork the repository and make a focused branch for a small correction.
2. Edit the relevant `skills/<name>/` folder. Keep `SKILL.md` frontmatter (`name` and `description`) valid and include every reference or helper the skill needs. Preserve existing examples unless you can explain the correction.
3. Test the workflow in a compatible SlotVFX Desktop build when the change claims runtime behavior. In the pull request, give the app version, MCP client, reproduction steps and observed result. Label anything you could not run as untested.
4. Check relative links and helper-script syntax. Do not add credentials, private project files, customer art, downloaded reference media, or another person's code without a compatible license and required attribution.
5. Open a pull request against the default branch. A SlotVFX maintainer reviews and merges it. Opening a pull request does not grant direct write access or trigger an automatic release.

By submitting a contribution, you confirm you have the right to submit it under this repository's MIT License. Keep third-party links as citations; do not claim their content is covered by this license. For security concerns, avoid posting secrets in issues or pull requests and use the contact route on [slotvfx.com](https://slotvfx.com/contact.html).
